# Store format

Byte-compatible with Angel's vault and the Python `sec` toolkit. The
conformance suite (`tests/vectors/`, generated by the vendored
`make_vectors.py`) pins every byte below: any format change needs a
version plan, migration notes, and new vectors — never a quiet edit.

## Layout

One file per secret. The address maps to a path segment by segment;
the last segment takes a suffix:

```
STORE/                              0700
  .salt                             0600, 32 random bytes, presence marker
  TELEGRAM/BOT/ESTIFIE.enc          0600, encrypted (below)
  TELEGRAM/CHATID/ME.plain          0644, raw bytes, unencrypted
```

`.salt` only marks "a store lives here"; the key is held in the
Keychain, not derived from the salt. When `.enc` and `.plain` twins
exist at one address, the encrypted file wins.

## Encrypted files

```
offset  size  content
0       4     magic "SEC2"
4       12    random nonce
16      *     AES-256-GCM ciphertext + 16-byte tag
```

The cipher is AES-256-GCM with a 32-byte key; the normalized address
is the associated data, so a file copied to another address never
opens. Minimum length is 32 bytes (magic + nonce + 1 framing byte +
tag); shorter files, and wrong magic, are format errors.

## Plaintext framing

The first decrypted byte names the shape:

- `T`: text — the rest is the value bytes as-is.
- `F`: file — one length byte, that many name bytes (UTF-8), then the
  file data.

Anything else after decryption reads as text from the second byte
(the historical shape); truncated file layouts are format errors.

## Key

32 bytes, base64, in a generic-password Keychain item (account
`master`). Reads try `est-vault`, then `angel-vault`, then
`estifie-sec`; writes go to the explicit service or `est-vault`.
